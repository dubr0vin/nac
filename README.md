# NAC — Not Another Calendar

Личный календарь: события, участники и личные тэги. Go / Echo / GORM / SQLite,
React / Mantine Schedule. Один процесс, одна база, без CalDAV.

## Локальный запуск

Требуются Go 1.26+, Node.js и C-компилятор для SQLite-драйвера GORM.

```sh
git clone https://github.com/dubr0vin/nac.git
cd nac
cd web
npm ci
npm run build
cd ..
NAC_DEV_USER=dmitry go run .
```

Открыть http://127.0.0.1:8080. `NAC_DEV_USER` действует только для соединений
с loopback и предназначен для разработки. База создаётся в `data/nac.db`.
Для разработки UI можно отдельно запустить `cd web && npm run dev`:
Vite передаёт API-запросы серверу на 8080.

## Продакшен

GitHub Actions собирает и публикует `ghcr.io/dubr0vin/nac:latest` при push в `main`.
Сборку можно запустить вручную на вкладке Actions. Для локальной сборки:

```sh
podman build -t nac -f Containerfile .
```

Настройки процесса:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `NAC_ADDR` | `127.0.0.1:8080` | Адрес HTTP; в контейнере `0.0.0.0:8080` |
| `NAC_DB` | `data/nac.db` | SQLite; в контейнере `/data/nac.db` |
| `NAC_TRUSTED_PROXIES` | `127.0.0.1/32,::1/128` | Разрешённые адреса/CIDR непосредственного прокси |
| `NAC_DEV_USER` | пусто | Локальный пользователь для разработки |

Контейнер работает под UID 65532. Ему нужен записываемый том `/data`.
Публиковать порт на хосте не требуется: прокси подключается по контейнерной сети.
Задать `NAC_TRUSTED_PROXIES` для фактического адреса прокси. `Remote-Sub` —
стабильный идентификатор, `Remote-User` — логин, `Remote-Name` — отображаемое имя.
На прокси удалить входящие `Remote-*` и подставлять только проверенные значения.

Маршруты `/export.ics`, `/view`, `/view/data` и `/api/sources/{id}/import`
должны обходить браузерный forward auth: приложение проверяет UUID экспорта или
Bearer-токен источника. `/assets/*` — общие публичные файлы интерфейса.
Все остальные `/api/*` требуют прокси-авторизации. Фронтенд сам не содержит данных.
Не задавать глобальный `X-Frame-Options` для `/view`: это маршрут для iframe.

Исходники: [github.com/dubr0vin/nac](https://github.com/dubr0vin/nac).

## Как устроено

- `main.go` — запуск, маршруты, доверие прокси, пользовательские настройки.
- `model.go` — модели GORM, условия тэгов и разворачивание повторений.
- `events.go` — события, права участников и личные тэги.
- `import.go` — источники, общий импортёр и таймер pull.
- `export.go` — отбор полей, ICS и данные киоска.
- `web/src/` — интерфейс, YAML-настройки и формы.

GORM создаёт схему при запуске. Структурированные поля событий и деревья правил
хранятся в JSON-колонках SQLite. Права проверяются сервером перед выдачей данных.
Отдельного слоя repository/service нет.

Тэги серии наследуются вхождениями; личные исключения содержат добавления и удаления.
Имена `ics:*` принадлежат импортёру. Исчезнувшие события источника сохраняются как
удалённые записи, чтобы повторное появление UID восстановило личные тэги.

## Редактор событий

`/event` — отдельная страница: форма слева, `ResourcesSchedule`
выбранных участников справа. Поиск показывает до 20 совпадений; выбранные люди
отображаются чипами в поле. Только текущее событие можно двигать и растягивать.
Клик по слоту переносит событие с сохранением длительности. Изменения остаются
в черновике формы до сохранения. Расписания обновляются одним пакетным запросом
с пользовательским интервалом опроса; сервер скрывает чужие детали событий.

Новые события используют часовой пояс пользователя. Права: все участники или
только автор. Сервер фиксирует автора при создании; для старых событий автор
восстанавливается из первого участника (прежний порядок создания события).
Личные тэги и отмена в этой форме не редактируются.
По клику на событие в календаре открывается popover: личные тэги переключаются
и сохраняются сразу. У повторяющегося события тэги меняются для выбранного
вхождения; отдельные кнопки открывают редактор вхождения или всей серии.

## ICS и push

Один источник — один полный снимок. URL pull, файл и POST используют одинаковый
импортёр. Отсутствующие UID удаляются из активного расписания; ошибка не меняет
события. Пустой корректный VCALENDAR очищает источник. Размер файла — до 16 MiB.

Создать источник в UI, выдать токен и сохранить его в своём скрипте:

```sh
curl -H "Authorization: Bearer $NAC_TOKEN" \
  -H 'Content-Type: text/calendar' \
  --data-binary @events.ics \
  'https://YOUR_HOST/api/sources/SOURCE_ID/import'
```

Токен выдаётся только один раз; сервер хранит его SHA-256. Замена или отзыв токена
не затрагивает другие источники. Pull-интервал настраивается отдельно у каждого
источника; `0` отключает обновление. Планировщик проверяет источники каждые 10 секунд.

Поддерживаются VEVENT, UID, RRULE от ежедневных до ежегодных повторений, RDATE,
EXDATE, RECURRENCE-ID, события на весь день и IANA-пояса. Плавающее время берётся
в поясе источника. `CATEGORIES` превращается в `ics:`-тэги. Чужой ATTENDEE не
предоставляет доступ к событию в NAC.

Неподдерживаемые конструкции (например VTODO, EXRULE, RDATE PERIOD,
RECURRENCE-ID RANGE или неизвестный TZID) отклоняются с ошибкой. Будильники и
произвольные расширения ICS не импортируются. При экспорте именованные пояса передаются как IANA TZID: клиент должен
знать эти пояса; собственные VTIMEZONE-определения не генерируются.
Частые повторения быстрее одного дня пока не поддерживаются. Разворачивание ограничено 200 000 шагов на серию.

## Экспорт и киоск

В настройках экспорта условие по тэгам задаётся YAML (тот же синтаксис, что у `busy`),
а разрешённые поля выбираются из списка. Если убрать все дополнительные поля,
останется только время, без SUMMARY. Исходный ICS никогда не отдаётся целиком:
выход строится из разрешённых полей.

После сохранения кнопка «Режим киоска» открывает отдельный диалог: вид, тема,
часовой пояс, интервал обновления, ссылка и код iframe. Эти настройки сохраняются
отдельно от условия и полей экспорта.

- `/export.ics?id=UUID` — подписка ICS.
- `/view?id=UUID` — представление для экрана или iframe.

UUID предоставляет доступ к выбранным данным любому обладателю ссылки.
Отзыв закрывает оба маршрута; киоск очищает данные при следующем опросе.
Скопированные ранее файлы отозвать невозможно.

## Проверки и резервная копия

Сначала собрать UI (он встраивается в Go-бинарник), затем:

```sh
go test -race ./...
cd web
npm run build
```

Для согласованного бэкапа работающей базы использовать SQLite backup API,
например `sqlite3 data/nac.db '.backup backup.db'`. Или остановить приложение
и скопировать весь каталог данных. Не копировать один `.db` при активной записи
без учёта WAL. Для восстановления остановить NAC и заменить файл базы бэкапом.

## Интерфейс

Имя пользователя справа открывает настройки и переключение русского/английского
языка. Выбор языка сохраняется в браузере. Часовой пояс по умолчанию берётся с
устройства; другой можно выбрать в настройках. Клик по пустому времени создаёт
событие, выделение диапазона задаёт его длительность.

Личные тэги, тэги по умолчанию, занятость и цветовые правила задаются YAML.
Часовой пояс и интервал обновления остаются обычными полями. Пример —
[settings.example.yaml](settings.example.yaml). Справка и промпт для LLM есть
в настройках. Комментарии сохраняются; ошибки YAML не меняют действующие настройки.

Условия: `true`, `false`, `{tag: имя}`, `{not: условие}`, `{and: [условия]}`,
`{or: [условия]}`. Пустой `and` совпадает со всем, пустой `or` — ни с чем.
Побеждает первое цветовое правило; последнее должно быть `when: true`.
`color: blue` задаёт заливку, `color: [blue, orange]` — голубую заливку, оранжевую полоску слева и кружок перед названием.
Поддерживаются имена палитры Mantine: `dark`, `gray` (или `grey`), `red`, `pink`,
`grape`, `violet`, `indigo`, `blue`, `cyan`, `teal`, `green`, `lime`, `yellow`, `orange`.
Фон и текст задаёт штатный вариант Mantine `light` для первого цвета; для полоски и кружка используется насыщенный второй цвет. HEX `#RRGGBB` тоже работает, в том числе в паре с именем. Цвета личные; киоск использует правила владельца, не раскрывая его тэги.

Источники и экспорты пока настраиваются формами. Чужое расписание открывается
по ссылке экспорта; выбор участника в редакторе события показывает его занятость.

## Проверки

```sh
cd web
npm test
npm run build
cd ..
go test ./...
```

Проверяются в том числе переходы летнего времени, миграция старых прав и настроек,
права участников, импорт/экспорт и отсутствие записей в БД при опросе расписания.
Ошибки API содержат `code` и `params`; интерфейс переводит их на выбранный язык.
Личные настройки сохраняются через `PUT /api/settings/config` (YAML, пояс и интервал).
